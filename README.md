# Hybrid Feature Fusion Framework for Just-in-Time Software Defect Prediction

A multilingual machine learning framework for **Just-in-Time Software Defect Prediction (JIT-SDP)** that combines traditional software change metrics, CodeBERT semantic representations, and structured LLM-derived semantic features.

The project investigates whether semantic information extracted from source-code changes provides complementary information to traditional JIT metrics for predicting defect-inducing commits under a **project-wise chronological evaluation protocol**.

---

## Research Objective

Traditional JIT software defect prediction primarily relies on handcrafted software change, process, ownership, and developer-experience metrics.

This project investigates whether defect prediction can be enhanced by combining:

- Traditional JIT change metrics

- CodeBERT semantic representations

- Structured LLM semantic features

The framework evaluates the feature sources independently, in pairwise combinations, and in full three-way fusion configurations.

The study also investigates whether the LLM representation can be reduced substantially while maintaining comparable predictive performance.

# Evaluation Protocol

## Project-Wise Chronological Split

Random train/test splitting is not used in the final experiments.

Each project is sorted chronologically using:

1. Parsed `author_date`

2. Deterministic source-row ordering as a tie-breaker for equal timestamps

Each project is then divided into:

```text

Oldest 70% → Training

Next 15%   → Validation

Newest 15% → Test

```

### Final Split

| Split | Rows | Buggy | Buggy Prevalence |

|---|---:|---:|---:|

| Training | 41,998 | 11,912 | 28.36% |

| Validation | 8,998 | 2,082 | 23.14% |

| Test | 9,000 | 1,376 | 15.29% |

| **Total** | **59,996** | **15,370** | — |

This protocol simulates predicting defects in future commits using information available from earlier commits.

No commit appears in more than one split.

# Leakage Prevention

The final pipeline follows strict leakage-control rules.

### Training-only operations

The following operations are fitted exclusively on the training split:

- PCA

- One-hot encoding

- Numerical imputation

- Mutual Information feature selection

- Correlation-based redundancy filtering

The learned transformations are then applied unchanged to validation and test data.

### Validation-only operations

Validation data is used for:

- ensemble selection

- probability-blend weight selection

- model/configuration comparison

### Test set

The final test set is kept separate from model construction and feature-selection procedures.

No test performance is used to select:

- features

- preprocessing parameters

- ensemble weights

- models

- experimental configurations

# Feature Sources

## 1. Traditional JIT Metrics

The final JIT representation contains **12 features**.

| Feature | Description |

|---|---|

| `la` | Lines added |

| `ld` | Lines deleted |

| `nf` | Number of modified files |

| `ns` | Number of modified subsystems |

| `nd` | Number of modified directories |

| `ent` | Entropy / distribution of changes |

| `ndev` | Number of developers associated with modified files |

| `age` | Average time since previous modification |

| `nuc` | Number of unique changes |

| `aexp` | Author experience |

| `arexp` | Recent author experience |

| `asexp` | Subsystem experience |

The obsolete `fix` feature is **not included** in the final 12-feature JIT representation.

---

## 2. CodeBERT Semantic Features

CodeBERT is used to obtain semantic representations of commit changes.

## Original Representation

```text

768 dimensions

```

The original CodeBERT representation is reduced using Principal Component Analysis.

## PCA Reduction

```text

768 → 384 dimensions

```

PCA is fitted **only on the training embeddings**.

The 384-dimensional representation retains approximately:

```text

99.43% of training-set variance

```

The resulting conceptual features are:

```text

codebert_pca_1

codebert_pca_2

...

codebert_pca_384

```

Reduced CodeBERT representations are also evaluated using:

- First 25 PCA components

- First 50 PCA components

- Train-only Mutual Information feature selection

## 3. LLM Semantic Features

The LLM pipeline extracts structured semantic information from software changes.

Seven semantic dimensions are used:

1. Intent

2. Change

3. Risk

4. Complexity

5. Scope

6. Test

7. Security

For every dimension, the extraction provides:

- A categorical semantic label

- A confidence value

- A margin value


```text

```

The complete model representation becomes:

```text

+ 384 CodeBERT

+ 14 LLM

----------------

410 features

```

The purpose is to evaluate whether the continuous confidence/margin information retains comparable predictive information without the categorical LLM features.

# Experiment 9 — Redundancy-Aware LLM Feature Selection

Experiment 9 evaluates an alternative compact LLM representation.

### Selection Procedure

1. Start with all 51 LLM features.

2. Compute train-only Mutual Information with the buggy label.

3. Apply Pearson correlation filtering using:

```text

|r| >= 0.90

```

4. For highly correlated features, retain the feature with higher training Mutual Information.

5. Reduce the 51 features to 44 non-redundant candidates.

6. Select the top 14 remaining features using training Mutual Information.

### Selected Features

```text

complexity_margin

scope_M

risk_confidence

scope_margin

complexity_M

test_M

test_confidence

security_margin

security_N

change_confidence

risk_M

change_OT

complexity_L

test_L

```

The final representation is:

```text

12 JIT

+ 384 CodeBERT

+ 14 selected LLM

----------------

410 features

```

The purpose is to determine whether generic relevance and redundancy filtering provides an additional benefit over the simpler confidence/margin representation.

# Fusion Strategies

## Early Feature Fusion

Feature representations are concatenated before model training.

Example:

```text

JIT + CodeBERT

=

12 + 384

=

396 features

```

Full fusion:

```text

12 + 384 + 51

=

447 features

```

---

## Probability Stacking

Independent base models generate validation prediction probabilities.

These probabilities are supplied to a Logistic Regression meta-learner.

The meta-learner is trained using validation predictions and subsequently applied to test predictions.

---

## Weighted Probability Blending

For multiple models:

```text

P_blend = w1 P1 + w2 P2 + ... + wk Pk

```

where:

```text

sum(wi) = 1

```

Weights are selected using the validation split.

For the later three-model experiments, the candidate models are:

- Random Forest

- XGBoost

- LightGBM

The selection procedure uses:

1. F1

2. MCC

3. ROC-AUC

4. PR-AUC

as the tie-breaking hierarchy.

# Evaluation Metrics

Each experiment reports both ranking-based and threshold-dependent metrics.

## Threshold-Independent

### ROC-AUC

Measures ranking/discrimination performance across classification thresholds.

### PR-AUC

Average Precision from the Precision-Recall curve.

PR-AUC is particularly useful under the observed class imbalance and temporal prevalence shift.

# Key Diagnostic Findings

The diagnostic experiments identified several important observations.

### Temporal Prevalence Shift

Buggy prevalence decreases across the chronological splits:

```text

Train       28.36%

Validation  23.14%

Test        15.29%

```

This shift is preserved rather than corrected using random resampling.

### Threshold Effects

Threshold-dependent metrics can change substantially under class imbalance and temporal prevalence shift.

Therefore, ROC-AUC and PR-AUC are reported alongside Precision, Recall, F1, and MCC.

### CodeBERT Signal

CodeBERT provides measurable semantic information, although its performance characteristics differ from traditional JIT metrics.

### Fusion Is Not Automatically Beneficial

Increasing the number of features does not guarantee improved predictive performance.

Different feature representations and fusion mechanisms are therefore evaluated experimentally.

### LLM Compactness

Experiment 8 demonstrates that the 51-feature LLM representation can be reduced to 14 confidence/margin features while retaining comparable predictive performance in the full JIT + CodeBERT setting.

### Redundancy-Aware Selection

Experiment 9 did not demonstrate an additional improvement over Experiment 8 using generic Mutual Information and correlation-based redundancy filtering.

```text

Traditional JIT Metrics

CodeBERT Semantic Representation

        +

LLM Semantic Features

```

The experimental progression is:

```text

LLM

JIT + CodeBERT

JIT + LLM
```

The primary research focus is to determine whether these heterogeneous representations provide complementary information for **chronological multilingual JIT software defect prediction**, while also examining whether semantic feature representations can be made substantially more compact without materially changing predictive performance.
